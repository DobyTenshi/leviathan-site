三条路径，读懂整张图

01 / 消息来回

入站 → IM → 路由 → 会话运行 → 宿主 LLM

路由选择焦点与角色，宿主驱动对应会话。回复经 IM 送达；交付不等于已读。Web、IM 与 main 会话不同，宿主相同。

02 / 记忆整理 · 规划

72h 且离开窗口 → 摘要 → 用户记忆 → 按任务检索

超过 2～3 天且离开最近窗口的消息才进入整理。首版建议 72 小时、最近 20 条，可配置；未完成任务、待答复与必要指代需 pin 保留。保留可解析原文引用，按来源的保留与访问规则查找；纠错与撤回同步。摘要不授予权限；归档任务尚未运行。

03 / 演进发行 · 规划

候选 → 实验 → 独立验收 → 插件发行 → 观察 / 回退

进化模块生产候选，发行模块管理不可变组合、配置与迁移。目标通过公开契约协作，回退保留新增消息与业务事实；宿主外恢复底线始终保留。

模块职责清单

状态是这张草图的注记，不是部署承诺。已有基础、源码候选与规划未部署分别阅读；角色权限检查也不等于操作系统安全隔离。

已有基础

lev-im · 消息入口

接收消息并送达回复，持有 IM 原文与通道上下文；送达不代表用户已读。原文仍属于 IM / 宿主，记忆层保存解析后的引用。

lev-router · 路由

选择会话与角色，整理跨会话上下文。现有路由 service 仍调用脚本并有多处 fallback，尚未完全解耦；候选代码不等于正式运行版本。

lev-core · 会话运行

DSH / Cordis 宿主管理 Web、IM、main 各自独立的会话、native source 与取消。它们共享同一宿主，并非三套独立系统。

已有基础

宿主 LLM · 可替换接入

角色与路由已有宿主公开 LLM 调用，目标记忆摘要也使用同一能力，由 provider 适配器连接模型。已有 @deepseek-ai/dsh-agent-default-model 与 @deepseek-ai/dsh-llm-pi-ai 配置基础；不再叠加 lev-llm 代理。更换提供商须验收工具、结构输出和媒体能力；换模型不换用户身份或记忆。

lev-presets · 角色

chat 是 Levi 的对外沟通、搜索资料与提醒角色；main 承担系统维护迭代。候选实现包含工具与业务权限检查，但不是操作系统安全沙箱，也不代表完整隔离已经完成。

源码候选

lev-bus · 任务交接

当前是由 core 相对导入的代码库，配合 task-pump 与 dispatch 脚本运行。目标是独立 taskCoordinator 插件；自动任务链仍在返工，尚未成为独立、验收通过的协调服务。

当前暂停

定时与事件驱动

systemd timers → 脚本，与 DSH schedule → 会话，是两套独立机制。7 个 timer 与 DSH schedule 当前均停用，原生 goal 续跑另算。目标按事件或计划调用公开服务，无工作不唤醒模型。

规划 · 未部署

lev-memory · 记忆

新插件目标：解析来源引用、事实主张与事件，管理 IM 热窗口归档摘要、用户记忆和按任务检索；规划 archiveConversation / queryArchive 契约。摘要是可纠正的衍生信息，不是授权；纠错与撤回必须同步。原文仍存在且有权限时可按引用查找，证据缺失如实返回。

规划 · 未部署

公开 contracts · 契约

共享的接口、schema与事件协议，让路由、任务、记忆、控制台与演进模块协作，明确事实归属与版本兼容；它不是一个顺次处理消息的服务。虚线表达目标联系，并不声称已有完整隔离。
